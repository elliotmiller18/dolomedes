"ownership" means maintaining a list of seeders for a file, and you can check if a node "owns" a file by asking if they have a seedlist.
a seedlist is built gradually by 1. requesting seeders from other owners and 2. recording STORE requests at that file id from prospective seeders.

Nodes can determine a "catch radius" (name sucks) which we'll call c and determines how many files they'll track.

Nodes should then maintain a list of all files that it shares at least c leading zeroes with. It should keep track of its peers that also
own the file. 

If a node knows more than k nodes (currently k bucket size but this constant could be sourced in many ways) that have proven ownership, a node is permitted
(but not required) to drop ownership. This could probably a be a "low-resource" mode where nodes don't have to own as many files and therefore handle
as many requests.
